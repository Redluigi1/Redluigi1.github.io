(03) Case study 01 / 04 · Ola Electric

A pipeline that learns from its own mistakes.

Technicians were claiming replacements for healthy parts and reselling the originals. Reviewing 1,500 claims a day by hand didn't scale and didn't catch it. So we built agents that read the evidence the way a senior reviewer would, and a loop that turns every disagreement with a human into a better rulebook.

agreement with human reviewers
86%
version v1.0
  1. 01 / Claim

    A claim comes in

    A technician files a replacement with evidence: voltage readings, part diagnostics, SOP videos. The scooter's telematics come along too, often thousands of raw sensor readings.

  2. 02 / Agent

    One agent per part

    Motor, battery, VCU and BMS each get a dedicated LangGraph agent with that part's SOP and failure signatures. I compressed telematics with PAA into a few hundred segments, which cut token cost roughly in half without losing the signal.

  3. 03 / Audit

    Humans audit a sample

    Every day, reviewers check a slice of decisions and flag disagreements: wrong approvals, wrong rejections, and right answers reached for the wrong reason.

  4. 04 / Classify

    Separate signal from noise

    Each disagreement is structured and labelled as a missing rule, an ambiguous rule, two rules in conflict, or a one-off slip. A fix is only proposed once several similar misses cluster together, so the prompt doesn't rot into contradictions.

  5. 05 / Patch

    Patch at the anchor

    The policy lives in one large prompt with anchors marking where each piece of logic sits. Fixes land surgically at an anchor instead of rewriting the whole thing, which is also where a big chunk of the token savings came from.

  6. 06 / Verify

    Golden set, then shadow traffic

    Every patch runs against a golden set: the cases that triggered it plus nearby cases it used to get right. Then a day in shadow on live traffic. A false approval costs real money, so anything that could raise them waits for a human sign-off.

  7. 07 / Ship

    Promote, keep every version

    Passing patches go live, every version is kept for instant rollback, and the loop starts again tomorrow. Agreement with human reviewers went from 86% to 90%, and daily claims dropped from 1,500 to 500.

(03) Case study 03 / 04 · Research, IIT Guwahati

Agents that argue, then check each other's work.

Argument mining turns prose into a graph of claims, premises and the links between them. The usual answer is a fine-tuned model, which needs piles of labelled data and stumbles on unfamiliar text. With Prof. Ashish Anand, I made the opposite bet: no fine-tuning at all, just three agents and very carefully chosen examples.

  1. 01 / Remember

    Index meaning and shape

    Every training paragraph is stored twice: as an embedding in ChromaDB, and as a discourse tensor from a DMRST parser that captures how the argument is built. Spectral similarity links paragraphs with the same shape into a NetworkX graph, whatever they're about.

  2. 02 / Retrieve

    Find examples that think alike

    A new paragraph pulls its five nearest neighbours by meaning, expands two hops through the structure graph to about fifteen candidates, and keeps the five that score best on a blend of semantic and discourse similarity.

  3. 03 / Argue

    Extract, relate, critique

    One agent extracts claims and premises, one maps supports and attacks, and a reviewer checks the graph for logical holes. If it fails, the feedback goes into a shared state and the agents try again, up to three rounds.

(03) Case study 04 / 04 · Ola Krutrim, Ola Maps

Fifty million searches a day, one address at a time.

Indian addresses don't follow a format. People type a flat number, a landmark, half a locality and a pincode, in any order. As an intern on Ola Maps I worked on both ends of a ride: finding the place, then predicting when you'll get there.

  • Search

    Productionised a spaCy NER address parser for autocomplete and forward geocoding, after benchmarking it against BERT-style transformers. Live, it lifted top-3 search accuracy by 2%.

  • ETA

    Retuned the live historical ETA lookup with Bayesian optimisation in Optuna, on cyclic time features and geospatial ones. 60% of rides now land within 10% of the predicted ETA.

  • Thin data

    Tier-3 cities don't have enough rides to learn from, so I clustered location services and road segments into sub-city zones with DBSCAN. Error there dropped by about 3 minutes.

  • Highways

    Traced a systematic ETA overestimate on long highway segments back to the dataset logic and fixed it, and patched routing anomalies on newly built links.

  • EV pings

    Showed that electric-vehicle ping data was dense enough to feed routing models, and tested bucketing schemes for predicting segment popularity.

(04) Selected work

More things I've shipped

  • Generic RAG falls apart on legal text, where one answer needs clauses stitched together from different documents. We built on LLMCompiler, so a planner lays out a DAG of retrieval tasks up front and independent sub-queries run in parallel.

    Retrieval goes through Voyage-Law2 and Cohere reranking, then an auto-merger that rejoins clauses split mid-chunk. A joiner grades whether the evidence actually answers the question and replans if not, falling back to a beam-search retriever for multi-hop chains, then to a human. Claude and OpenAI back each other up so one outage can't take it down.

  • When an airline changes its schedule, thousands of passengers have to be moved onto other flights without breaking PNR priority, cabin class, connection times or special passenger needs. For Mphasis's problem at the 12th Inter-IIT Tech Meet, we built a rule engine that scores every PNR and every candidate flight, then solves the reassignment as a mixed-integer program.

    We solved it classically with Gurobi and as CQM and BQM formulations on D-Wave's quantum annealer, and sped up preprocessing with prune-and-search, multithreading and dynamic programming. The rules live in a Streamlit UI, so an operations team can retune them without touching code. It took gold, first of 20 IITs.

  • Scanned medical PDFs mix lab tables, prescriptions, discharge notes and X-rays on the same pages, and one generic prompt kept hallucinating structure. I split the job across 14 narrow MedGemma agents on Vertex AI, plus a YOLOv8 model I fine-tuned on a 301-image dataset I annotated myself to find scans inside PDFs. Every detected crop gets a second opinion from an LLM before it's accepted.

    A shared report summary feeds the downstream agents so nothing re-reads raw pages, and a layered JSON repair chain keeps structured output from breaking. In the UI you can draw a box on a scan and ask about just that region.
